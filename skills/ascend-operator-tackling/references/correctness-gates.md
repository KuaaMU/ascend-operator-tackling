# 正确性、语义与数值门禁

## 目标

在真实目标环境证明实现满足完整 API 契约，而不是只对 benchmark 主路径给出“看起来正确”的数。

## 一、建立语义 Contract

在写 kernel 或改 route 前写清：

- 输入/输出布局、类型、stride、shape 和别名规则；
- 索引基准、广播、padding、空输入和非法输入；
- 结果写回范围；
- 异步/同步语义；
- 异常值、奇异/退化、极值和特殊模式；
- 参考实现、误差公式、阈值和精确一致字段；
- fast path 允许跳过的条件，以及未命中时的 fallback。

每条规则注明确切来源。任务书、官方 API 文档、上游实现和测试生成器冲突时，先暂停依赖该规则
的优化。

## 二、参考实现

参考实现应独立于被测实现：

- 对算法实现，使用明确的 CPU/host oracle；
- 对库算子，使用官方或行业参考库；
- 对整数、索引、状态和元数据，优先精确一致；
- 对浮点计算，使用目标规定的容差、匹配率和绝对误差规则；
- 对 NaN/Inf、符号零和异常传播，写清预期语义。

参考实现自身必须被测试。若 oracle 有 bug，错误结论会污染整条路线。

## 三、用例层次

### 基础功能

- 最小 shape；
- 典型 shape；
- 多 batch/多 block；
- 目标后端的主路径。

### 边界与非法输入

- 0、1、最大/最小合法值；
- 空指针、负维度、非法 stride/descriptor；
- padding、非连续和偏移地址；
- 尾块、非对齐、非整除；
- quick return 和不启动 kernel 的路径。

### 数值与结构对抗

- 随机、均匀、正态和混合分布；
- 对角占优、病态、奇异、退化；
- 极值、消去、溢出/下溢、NaN/Inf；
- 需要交换、重排、fallback 或特殊分支的输入；
- 连续调用、缓冲复用和状态残留。

### 实现内部

- fast 与 fallback 对相同输入一致性；
- 不同 tile/panel/route 的等价性；
- 多形状尾块；
- 多线程、多核、多 stream 和连续调用；
- reset 与不 reset 的语义差异；
- 缓存/workspace 生命周期。

## 四、Fast/Fallback 不变量

任何加速都不得绕过最终语义：

1. fast path 只能跳过已经被严格证明安全的工作。
2. 内部 marker、scratch、workspace 不得复用用户可见输出字段。
3. 未命中 fast path 的每个工作单元必须可到达 exact fallback。
4. fast 和 fallback 必须使用一致的分区、索引和输出范围。
5. fallback 不能依赖上一次调用残留的状态。
6. fallback 结果必须覆盖所有应写输出，不能只修一部分。
7. route 命中条件必须来自结构/资源模型；输入内容启发式只能在有证明和完整 fallback 时使用。

## 五、数值正确性

对浮点算子记录：

- precision/accumulation mode；
- 允许的重排、融合、降精度和补偿；
- FMA/收缩开关；
- 溢出、下溢、次正规数和 NaN/Inf 行为；
- ULP、相对/绝对误差、匹配率和 outlier 规则；
- 输出中存在未写值、padding 或 don't-care 区域的规则。

性能优化改变算术顺序或精度后，必须重新跑完整正确性门，不能沿用旧精度结论。

## 六、并发和状态

检查：

- kernel 内线程/流水依赖；
- AIC/AIV 或其他执行单元之间的可见性；
- host stream/event 生命周期；
- workspace、executor、缓存 key 和复用条件；
- 相同 handle 连续调用、不同 stream、多个调用并发；
- 异常退出后的状态恢复。

竞态有时只在连续调用、高 batch 或特定缓存状态下出现。单次正确不构成并发证明。

## 七、门禁裁决

正确性 gate 通过必须满足：

- 语义 contract 全覆盖；
- 官方/用户指定精度口径通过；
- 边界和负向行为通过；
- fast/fallback 对抗用例通过；
- 多调用与状态复用通过；
- 失败输入、命令、日志、源码/二进制 hash 已归档；
- Reviewer 能独立复现至少一条关键证据。

存在任何未解释的正确性 P0/P1，禁止性能 promote。
