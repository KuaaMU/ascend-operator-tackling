# 自主循环、决策树与止损

## 目标

让 agent 在没有持续人工监督时，仍能根据目标、证据和资源自主选择下一步，并主动发现自己的
判断已经失效。自主不等于随意探索：每一轮都必须产生可验证信息、缩小不确定性或改善目标指标。

## 单轮状态机

```text
REANCHOR -> CLASSIFY -> BASELINE -> ATTRIBUTE -> HYPOTHESIZE
         -> PROBE -> GATE -> DECIDE -> PERSIST -> NEXT
```

### REANCHOR

重新核对：

- 最新任务书、验收标准、测试数据和用户约束；
- 权威分支/commit、worktree 状态、源码 hash、实际加载的二进制 hash；
- 目标设备、CANN/编译工具版本、设备占用和测试口径；
- 上一个 HANDOFF 的下一步是否仍然成立。

任何不一致都先记为 `stale` 或 `contradicted`。不要在一个来源不明的基线上继续优化。

### CLASSIFY

把问题分到一种主类别，禁止混成泛泛的“需要优化”：

| 类别 | 典型信号 | 首选动作 |
|---|---|---|
| 契约/语义 | 行为不确定、接口解释冲突、边界规则缺失 | 找一手来源、写可执行 contract |
| 正确性 | 数值错、越界、竞态、边界失败、fallback 不一致 | 最小反例、oracle、sanitizer |
| 环境/构建 | 工具缺失、版本不匹配、加载了旧二进制 | 环境发现、干净重建、hash 对照 |
| 性能关键路径 | 已正确但目标未达 | phase/route 归因、预算、结构实验 |
| 证据/状态 | 数字不可追踪、旧摘要冲突 | provenance 修复、重新测量 |
| 工程卫生 | 生产树含探针、route 污染、敏感信息 | 隔离、清理、交付审计 |

### BASELINE

选择一个能回答当前问题的最小基线：

- 正确性问题：最小失败输入 + 独立参考实现。
- 性能问题：目标 case + 当前路由 + 同机同构建基线。
- 稳定性问题：重复运行或多次调用，而不是单次最好值。
- 环境问题：最小 smoke，而不是完整 workload。

基线必须附带源码、二进制、环境、参数和原始数据路径。若复测与历史记录差异明显，先归因
环境、构建、输入、路由或测量方法，不要先改算法。

### ATTRIBUTE

先建立关键路径或误差传播账本。至少回答：

1. 当前时间/误差主要花在哪一段？
2. 哪一段是理论上不可压缩的 floor？
3. 哪一段受当前执行图、数据布局或同步限制？
4. 哪个数字只是观察值，哪个数字已经过独立测量？
5. 哪个改动有机会跨多个 case 泛化？

归因工具优先级和常见量级判断见 `official-tools.md` 与 `performance-gates.md`。

### HYPOTHESIZE

每个候选必须是可证伪的：

```text
基线：
目标 case/分布：
当前关键路径：
假设：
唯一变量：
预期变化方向和量级：
最小区分实验：
成功门：
kill criterion：
回退点：
可能影响的其他区间：
```

如果一句话说不清“哪个变量会改变哪个证据”，实验还不成熟。

### PROBE

按成本递增：

1. 静态证据：源码、编译产物、符号、hash、配置。
2. 最小运行：单 case、小 batch、单阶段。
3. 方向筛选：少量样本，仅判断方向。
4. 正式 gate：目标口径、目标样本量、全量回归。

探针不得直接污染生产分派。优先放在独立 worktree、独立路径或显式关闭的候选 route 中。

### GATE

按问题类别运行对应 gate：

- 正确性：`correctness-gates.md`
- 性能：`performance-gates.md`
- 证据与事实：`evidence-and-truth.md`
- 交付：`upstream-delivery.md`

Gate 是二元裁决，不按“趋势不错”通过。

### DECIDE

只允许五种裁决：

| 裁决 | 条件 | 后续 |
|---|---|---|
| promote | 所有 gate 通过，跨区间无回归 | 进入生产候选 |
| iterate | 方向正向但未达门，且失败原因清楚 | 保留单变量继续 |
| revert | 与基线无显著差异或未达最小收益 | 回退并冻结失败证据 |
| park | 当前资源/API 不可完成，但概念未证伪 | 写清重开条件 |
| close | 结构已被多次独立证据否定 | 写失败家族，禁止原形态重开 |

### PERSIST

至少更新：

- `STATE.md`：当前状态、尝试次数、下一步。
- `CANDIDATES.md`：候选结论与证据。
- `TRUTH.md`：新增/失效事实。
- `HANDOFF.md`：新 agent 的最短恢复路径。
- `LESSONS.md`：可复用失败模式。
- `METRICS.md`：本轮是否提高了攻坚效率，以及效率下降在哪里。

### NEXT

从最高优先级、最低不确定性收益比的未完成动作开始。不要因为上一条路线失败就随机换题。

## 自主纠错规则

### 结果与预测不一致

优先怀疑以下顺序：

1. 加载了错误二进制或错误版本；
2. 测试输入、reset、warmup、设备状态或统计口径变化；
3. 实际 route 与预期 route 不一致；
4. 观测工具过滤或采样方式错误；
5. 理论模型遗漏了同步、layout、launch 或 host 成本；
6. 最后才假设硬件异常。

### 连续三次无正收益

同一问题、同一结构连续三次满足以下任一条件即触发止损：

- 无稳定收益；
- 收益只出现在单个近门限 case；
- 每次都依赖不同参数组合；
- 需要扩大白名单才能维持收益；
- 正确性/稳定性证据无法闭环。

动作：

1. 停止参数扫描；
2. 回退到最近权威基线；
3. 写失败家族：问题、共同结构、已排除解释、剩余未知；
4. 重新做一次关键路径归因；
5. 只允许从新的结构假设重开。

### 任务目标变化

重新写 contract，标记失效证据，重新生成 PLAN。不要偷偷沿用旧指标或旧输入分布。

### 资源冲突

若设备、仓库或其他 agent 正在被占用：

- 不覆盖、不 kill、不重置他人的状态；
- 先寻找独立 worktree、设备或只读证据；
- 无法隔离时，停止有副作用动作并向用户升级。

## 何时暂停并请求用户

只有以下情况需要人工介入：

- 验收标准存在无法从一手资料解决的矛盾；
- 需要执行不可逆或高成本操作，且没有安全替代；
- 目标资源无法获得，继续只能产生低价值猜测；
- 连续多个结构家族被证伪，且没有满足目标的新路线。

请求时给出一页式材料：当前目标、已验证事实、已关闭路线、最小请求、两个可选方案和默认建议。
