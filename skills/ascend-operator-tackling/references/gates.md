# 通用门禁骨架

三道门，按顺序过。门是二元裁决：通过 / 不通过，没有"趋势不错"。

## 第一道：正确性门

WHEN 语义、边界、异常行为未闭环 THEN 禁止任何性能 promote。

通过条件：
- 语义 contract 已书面化（输入/输出、边界、非法输入、异常值、fallback 语义），
  每条规则注明确切来源；来源冲突时先暂停依赖该规则的优化；
- 有独立于被测实现的参考实现（oracle），且 oracle 自身被测试过；
- 用例分层覆盖：基础功能 → 边界/非法输入 → 对抗分布 →
  实现内部（多路径一致性、状态复用、并发）；
- 加速路径不得绕过最终语义：未命中必须有完整 fallback；
  内部状态不得污染用户可见输出；
- 改变执行顺序/精度后，必须重跑完整正确性门，不沿用旧结论；
- Reviewer 能独立复现至少一条关键证据。

## 第二道：性能门

**先定义"性能"**：口径（端到端/阶段/单点）、统计量（均值/中位数/P95）、
warmup/采样/输入恢复、环境（设备/负载/并发）——任一项变化视为新测量。
验收只接受任务书指定的口径，其他口径用于归因。

测量纪律：
1. 同机、同构建、同输入 A/B，变更前后都跑控制组；
2. 方向筛选可用小样本，promote 用正式样本量；
3. 不静默剔除异常；先用环境/调度/输入解释；
4. 跨 run 方差大时先测方差，不把近门限翻转当收益。

归因顺序：确认实际执行路径 → 端到端拆阶段账本 →
测 floor（不可压缩部分）→ 候选实验（单变量）。

WHEN floor 已超目标 THEN 停止调参数，必须改执行结构或重核目标。

Promote 条件：正确性门通过；目标口径通过；代表性集+全量回归通过；
无未解释的已通过区间回归；至少一次独立复现；关键区间收益有结构解释；
失败路线与回退点已记录；生产树无实验开关。

常见偷换（命中即打回）：用中位数代替任务书的均值；用局部耗时代表端到端；
用小样本代表正式通过；用理想输入分布代替通用语义。

## 第三道：交付门

- 生产树干净：无实验开关、调试打印、临时 patch、未接线代码、
  仅为单个测试用例加的特例；
- 一个提交只做一个逻辑变更；diff 只含目标变更；
- 随代码提交证据：构建命令、完整正确性测试、目标性能测试、
  回归测试、原始日志路径、源码/构建 hash、已知限制；
- Reviewer 独立验证通过；新 agent 能按 HANDOFF 复现。

## 领域特化

数值计算/加速器算子等领域的额外门禁（如浮点误差规则、
fast/fallback 不变量细则），见 `profiles/ascend-cann.md`。
