# 文档与信息去噪

## 目标

保留会改变行动的信息，降低重复、冲突和过期信息带来的上下文成本。文档越接近权威事实，
越应短、结构化、可追溯。

## 信息分层

### 权威层

`STATE`、`TRUTH`、`PLAN`、`REVIEW`、`CANDIDATES`、`HANDOFF`。

特点：

- 每条信息有 owner 和更新时间；
- 关键数字有 provenance；
- 同一主题只有一个权威版本；
- 只保留当前有效结论和明确被取代的引用。

### 证据层

`evidence/`、原始日志、profile、trace、CSV、JSON、dump。

特点：

- 不写叙事结论；
- 保留命令和环境；
- 文件名和 manifest 能定位 run；
- 大文件按需归档，不进入交付树。

### 过程层

`worklog/`、临时分析、探索笔记。

特点：

- append-only；
- 允许失败和假设；
- 定期提炼为事实、候选或 lesson；
- 不作为验收证据。

### 噪声层

重复摘要、无来源数字、旧 route 的中间结论、聊天转述、与当前目标无关的指标。

处理：

- 不进入权威文件；
- 必要时归档；
- 不反复在上下文中复述。

## 写文档的门槛

新增文档前回答：

1. 它承载哪个当前问题？
2. 现有文档能否容纳？
3. 谁是 owner？
4. 生命周期是永久、gate、session 还是临时？
5. 是否进入交付？
6. 何时归档/删除？

回答不清时，不新建。

## 事实写法

好的写法：

```text
F-012
statement: 该 route 在目标设备上未通过目标口径。
status: verified
source: evidence/<run>/manifest.md
scope: operator=<x>, version=<x>, device=<x>, shape=<x>
recorded_at: ...
```

差的写法：

```text
之前测过，效果不好。
```

## 数字写法

只保留可行动的统计：

- value + unit；
- 目标口径；
- 样本量；
- 统计量；
- 环境/版本；
- raw evidence path；
- 与基线的关系。

不要把每个中间数字都写进 STATE。只有会影响下一步决策的数字才进入权威层。

## 失败信息

失败实验最有价值的是：

- 假设是什么；
- 只改了什么；
- 预测与实测差异；
- 哪个机制被排除；
- 是否允许重开；
- 重开需要什么新证据。

不要只写“NO-GO”。没有共同机制的 NO-GO 会让后续 agent 重复劳动。

## 文档清理

每个 checkpoint 结束：

1. 把 worklog 中已验证结论提炼到 TRUTH；
2. 把候选结果写入 CANDIDATES；
3. 把可复用教训写入 LESSONS；
4. 把被取代报告标记或归档；
5. 删除无 owner、空内容、重复摘要；
6. 检查所有引用路径仍存在；
7. 更新 INDEX。

## 信息预算

优先保留：

- 当前关键路径；
- 当前 target 和 holdout；
- floor、预算、方差；
- 失败家族和关闭条件；
- 权威 hash 与恢复命令。

优先删除：

- 重复解释；
- 已被更强证据取代的推断；
- 不影响决策的历史日志摘要；
- 与目标口径无关的漂亮数字。
