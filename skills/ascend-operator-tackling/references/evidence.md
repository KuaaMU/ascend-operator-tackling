# 证据层级与 Provenance

## 证据层级

### A 级：目标环境可复现证据（验收与 promote 的必要条件）

- 目标环境的真实运行；
- 原始日志、trace、profile、CSV/JSON；
- 明确命令、源码/构建 hash、环境版本；
- 可独立复跑。

### B 级：受控过程证据（可用于归因与选实验，不能单独宣布通过）

- 单阶段 probe；模拟、静态分析、编译诊断；
- 小样本方向筛选；旧版本或邻近环境结果。

### C 级：外部/二手证据（只能形成假设，必须转成本地最小实验）

- 官方文档的未验证解释；上游 PR、论文、博客、他人报告；
- 与目标版本/环境不同的性能数字。

## 数字 Provenance

任何进入 STATE/TRUTH/REVIEW/交付报告的关键数字，必须能追溯：
value、unit、scope、机器/环境、源码 hash、构建 hash、命令、
输入/reset、warmup/采样、统计方法、原始证据路径、记录时间。

WHEN 数字缺 provenance THEN 它只能待在临时分析里，不能作为决策依据。

## 事实状态语义

| 状态 | 含义 |
|---|---|
| `verified` | 有原始证据或一手来源，并已独立核对 |
| `assumed` | 推进用的工作假设，不能作为最终结论 |
| `unverified` | 他人转述、未复现实验 |
| `stale` | 来源版本/代码/环境/口径已变化 |
| `contradicted` | 新证据与旧结论冲突，暂停使用 |
| `closed` | 已明确重开条件的否定结论 |

## 事实失效规则

以下变化必须让相关事实重新核验：验收口径变化；上游 HEAD/依赖版本变化；
工具链/环境变化；测试数据/种子/阈值变化；实际加载的构建变化；
worktree 变 dirty；发现旧结论只在特定分布/顺序/热状态下成立。

更新保留历史，不静默覆盖。冲突时：优先一手来源与目标环境原始证据；
强度接近则暂停依赖该事实的优化，设计最小实验区分。
